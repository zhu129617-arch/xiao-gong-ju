## 小蝶真机试用后报的第一个 bug（13:54 修完）

**现象**：自媒体页空状态下点「加一个选题」，毫无反应。

**根因**：空状态的主按钮动作是「去聚焦 `input[data-action="media:add-idea"]`」，但那个输入框只在**非空**状态下才渲染 —— 空状态下压根没有它。同一个错误在 **dev / consult / diet / games** 一共 5 个模块都有。

**修法**：新增 `ui.emptyStateWithInput()` —— 空状态**自带**输入框 + 主按钮，两者共用同一个 action，用 `ui.readFirstInput(el)` 取值（事件源是输入框就用它的值，是按钮就回同一块容器里找输入框）；空着点按钮用 `ui.focusFirstInput(el)` 把光标落到输入框上，绝不让按钮看起来像坏的。饮食的空状态要两个字段（名称 + 热量），手写一份。

**测试为什么没抓住（这次教训最值钱）**
- 原来的「动作必须都有实现」测试只验证 action **存在**，不验证它**有没有效果** —— 存在但无效的按钮照样通过。
- 新增 `tests/empty-state.test.js`：①五个模块逐一验证「空状态里回车能加上、加上后空状态退场」＋「点按钮也能加上」＋「空着点按钮要把光标落到输入框」；②通用检查「聚焦类动作指向的元素必须在同一份 HTML 里存在」。
- **这条通用检查自己也差点是空转的**：正则用了 `[^'"`]+`，而选择器里带着另一种引号（`'input[data-action="x"]'`），被中途截断 → 检查永远通过。是「检查器本身有效吗」那条自检测试抓出来的，改用反向引用才真有效。**教训：写通用检查一定要配一条"它抓得住老写法"的自检。**
